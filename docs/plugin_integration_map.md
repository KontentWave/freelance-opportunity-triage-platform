### Known acceptance boundary

Actual frozen-corpus counts are now measured under separately authorized operator exceptions: **20/20 pass, minimum 1,086 and maximum 1,127**, with DEMO-001 reused rather than recounted. Earlier substituted-contract and faked-HTTP tests are still only offline behavior evidence, not the source of those measurements. Production rejects counting while its billing/retention policy evidence is absent; the measured corpus does not close that gate. A future corpus change needs new approval/hash/version and a review of the independent hard-requirement predicates. The manifest is trusted server content, never a request-selected file.

A response settled on a different UTC day from its last dispatch authorization remains uncertain even with measured usage: suspension or connection establishment may have moved actual dispatch across midnight. Evidence-referenced reconciliation must explicitly supply the verified dispatch day; that day's budget row is created and locked before run/item/attempt state, and no new provider work follows reconciliation. This avoids assigning a delayed request to the previous day's spending allowance.

UI/report rendering/download and owner delivery remain 6.3/6.4 work. No shared documents, host settings or real external data were changed.

No external count was performed during that initial integration. Later separately authorized **one-request and 19-request exceptions** measured all 20 frozen requests despite unknown charges/endpoint retention; DEMO-001's **1,116** result was reused. No inference was performed. The approved MIME security patch is recorded above; model, rates and caps remain unchanged.
